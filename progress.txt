## Iteration 1 - US-001: Enable pgvector extension
- What was implemented: Created SQL migration to enable pgvector extension for vector embeddings
- Files changed:
  - supabase/migrations/003_enable_pgvector.sql (new)
- Learnings for future iterations:
  - Migration files follow pattern: NNN_description.sql (e.g., 003_enable_pgvector.sql)
  - Existing migrations: 001_create_network_profiles.sql, 002_add_profile_approval.sql
  - Typecheck command: `npx tsc --noEmit` (no yarn or npm typecheck script)
  - pgvector extension provides the `vector` data type for embeddings

## Iteration 2 - US-002: Create companies table schema
- What was implemented: Created SQL migration for companies table with all required columns, indexes, and RLS policies
- Files changed:
  - supabase/migrations/004_create_companies.sql (new)
- Learnings for future iterations:
  - Reuse `update_updated_at_column()` function from 001 migration for triggers
  - RLS policies use `auth.uid()` to check current user
  - Use `TO authenticated` in policies to restrict to logged-in users
  - Admin access handled via service role key (not RLS policy)
  - CHECK constraints can be used for ENUM-like validation (e.g., company_size)
  - Use UNIQUE constraint on user_id to ensure one company per user
---

## Iteration 3 - US-003: Create job_submissions table schema
- What was implemented: Created SQL migration for job_submissions table with all columns, CHECK constraints for enum-like fields, indexes, RLS policies, and updated_at trigger
- Files changed:
  - supabase/migrations/005_create_job_submissions.sql (new)
- Learnings for future iterations:
  - Use ON DELETE CASCADE for FK references when child records should be deleted with parent
  - RLS policies can use subqueries to check ownership through related tables (e.g., via company_id → companies → user_id)
  - Use IN clause in RLS for clarity when checking against a subquery result
  - VARCHAR(50) is sufficient for status/type enum-like fields
  - TEXT[] for array columns like preferred_skills and focus_areas
---

## Iteration 4 - US-004: Create job_matches table schema
- What was implemented: Created SQL migration for job_matches table to store AI-generated matches between jobs and profiles
- Files changed:
  - supabase/migrations/006_create_job_matches.sql (new)
- Learnings for future iterations:
  - Use CHECK constraint with range for numeric scores (e.g., match_score >= 0 AND match_score <= 100)
  - UNIQUE constraint can be defined using CONSTRAINT name UNIQUE (col1, col2) syntax
  - RLS policies can allow multiple access patterns (companies see approved matches, members see their own matches)
  - Use BOOLEAN DEFAULT NULL for three-state fields (null=pending, true/false for decided)
  - JSONB for flexible structured data like skill_matches
  - Add COMMENT ON TABLE and COMMENT ON COLUMN for schema documentation

## Iteration 5 - US-005: Add embedding column to network_profiles
- What was implemented: Created SQL migration to add vector embedding columns to network_profiles for semantic search
- Files changed:
  - supabase/migrations/007_add_profile_embeddings.sql (new)

  - Use `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` for idempotent migrations

## Iteration 10 - US-010: Create profile embedding generation utility
- What was implemented: Created utility function for generating vector embeddings from network profile data using OpenAI's text-embedding-3-small model
- Files changed:
  - src/lib/embeddings.ts (new) - embedding generation utility
- Functions added:
  - `buildProfileEmbeddingText(profile)` - combines profile data (bio, skills, focus areas, projects, enrichedContent) into embedding text
  - `generateProfileEmbedding(profile)` - generates 1536-dimensional embedding vector using OpenAI API with retry logic
- Learnings for future iterations:
  - Use Vercel AI SDK's `embed` function from 'ai' package: `import { embed } from 'ai'`
  - Use `openai.embedding('text-embedding-3-small')` for the embedding model (not `openai()` for chat models)
  - FOCUS_AREA_LABELS mapping converts internal values ('immersive-experiences') to human-readable text for better embedding quality
  - Retry logic uses exponential backoff: BASE_DELAY * Math.pow(2, attempt - 1)
  - Don't retry on validation/API key errors - only on transient failures
  - Include enrichedContent in embedding text to incorporate scraped portfolio data

## Iteration 12 - US-012: Create portfolio content scraping utility
- What was implemented: Created utility function to scrape and extract text content from member portfolio URLs for embedding enrichment
- Files changed:
  - src/lib/scraper.ts (new) - portfolio content scraping utility
- Functions added:
  - `scrapePortfolioContent(urls[])` - main function that accepts array of URLs, returns combined scraped content
  - `scrapeUrl(url)` - scrapes single URL with timeout handling
  - `extractTextFromHtml(html)` - extracts meaningful text from HTML (paragraphs, headings, main content)
  - `cleanContent(text)` - normalizes and deduplicates extracted text
- Features:
  - 10 second timeout per URL
  - 500ms delay between requests for rate limiting
  - Max 10,000 characters per URL to prevent memory issues
  - Skips LinkedIn URLs (requires authentication)
  - Removes nav, header, footer, sidebar content
  - Custom User-Agent identifies the bot
- Learnings for future iterations:
  - Use AbortController with setTimeout for fetch timeouts
  - LinkedIn and similar authenticated sites cannot be scraped directly
  - Extract from semantic HTML elements (article, main, section, p, h1-h6, li)
  - Filter content by minimum length (20 chars) to avoid noise
  - Sequential processing with sleep() for rate limiting
  - Return both individual results and combined content for flexibility
