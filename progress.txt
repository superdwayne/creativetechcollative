## Iteration 3 - US-003: Create job_submissions table schema

- Files changed:
  - supabase/migrations/005_create_job_submissions.sql (new)
- Learnings for future iterations:

  - RLS policies can use subqueries to check ownership through related tables (e.g., via company_id → companies → user_id)
  - Use IN clause in RLS for clarity when checking against a subquery result
  - VARCHAR(50) is sufficient for status/type enum-like fields
  - TEXT[] for array columns like preferred_skills and focus_areas

## Iteration 15 - US-015: Create vector similarity search function
- What was implemented: Created SQL database function and TypeScript wrapper for vector similarity search using pgvector
- Files changed:
  - supabase/migrations/008_create_similarity_search_function.sql (new) - PostgreSQL function for cosine similarity search
  - src/lib/supabase.ts (modified) - added findSimilarProfiles() function and ProfileWithSimilarity interface
- Functions added:
  - SQL: `find_similar_profiles(query_embedding, match_limit, similarity_threshold)` - returns profiles with similarity scores

- Learnings for future iterations:
  - pgvector doesn't work directly with Supabase JS client - need to create SQL functions and call via `.rpc()`

  - SQL function uses `SECURITY DEFINER` to run with function owner permissions
  - Format embedding vectors as string `[${embedding.join(',')}]` when passing to RPC
  - Filter availability to 'open-to-work' or 'open-to-collaborations' using `IN ('open-to-work', 'open-to-collaborations')`
  - Order by distance ASC (lower = more similar) to get best matches first
